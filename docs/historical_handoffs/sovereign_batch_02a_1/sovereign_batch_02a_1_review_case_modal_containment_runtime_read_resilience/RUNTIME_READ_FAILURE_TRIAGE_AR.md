# تشخيص آمن لرسائل runtimeRepository `fetch failed`

## ما تعنيه الرسائل
تشير إلى أن طبقة خادم المساعد حاولت قراءة جداول المراجع/الملفات/الاستشهادات المرتبطة، وفشل النقل الشبكي. لا تثبت هذه الرسائل وجود خلل في السجل نفسه، ولا يصح معها الاعتماد على حزمة معرفة ناقصة السند.

## ما تغير في 02A.1
- لا يتم إرجاع bundle ناقص بعد فشل قراءة مصدر/مرجع/ملف/استشهاد مرافق.
- يُستخدم fallback الحالي ويُطبق backoff قصير (30 ثانية) لتجنب تكرار التحذيرات لكل طلب.
- لا تُطبع مفاتيح أو أسرار.

## التحقق بعد التشغيل
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\inspect_local_assistant_runtime_connectivity.ps1
```

## تفسير النتائج
- صحة endpoint لا تعني أن كل query معرفي نجح؛ هي مؤشر إعداد/وصول عام فقط.
- أي استمرار لـ`fetch failed` بعد restart يتطلب فحص الاتصال الشبكي وقيم البيئة في عملية الخادم، دون مشاركتها في المحادثة.
- لا تعالج المشكلة بتعطيل RLS أو نقل service-role key إلى المتصفح.
